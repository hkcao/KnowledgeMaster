# 知屿 KnowledgeMaster 精确复刻 Prompt

> 本规格以当前 Tauri、React 和 Rust 实现及其自动化测试为准，不以产品设想代替已实现行为。

## 1. 你的角色与交付目标

你是一名资深桌面应用架构师和全栈工程师。请重新实现一款名为“知屿 KnowledgeMaster”的本地优先知识工作台，目标用户是长期阅读、批注、整理和横向比较科研论文的人。

交付物必须是可安装、可运行、可测试的桌面应用，而不是静态原型。正式目标平台同时包括 macOS 14+ 与 Windows 10/11；两端共享同一套资料库格式、React 前端、Rust 业务逻辑和功能协议。界面语言默认中文。

本次实现使用：

- Tauri 2；
- React + TypeScript + Vite；
- Rust 后端命令；
- PDF.js 阅读与文字层；
- React Markdown + GFM + KaTeX；
- 不使用 Electron；
- 不引入向量数据库，不计算 embedding；
- 不依赖云端业务后端；
- 不上传整个知识库，只有用户发起 AI 请求时才发送明确授权的内容。

“精确复刻”指信息架构、核心交互、持久化语义、安全边界、AI 上下文策略和异常处理均与下面规格一致。不同 UI 框架允许像素级小差异，但不能删除流程或以占位按钮代替。

## 2. 产品原则与非目标

### 2.1 必须遵循

1. 本地优先：资料、主题、全文索引、批注、笔记、对话和摘要均保存在用户选择的资料库目录。
2. 原始资料安全：AI Agent 永远不能直接修改或删除知识库原件。
3. 虚拟组织：主题只保存关联关系；一份文档可以同时属于多个主题，不复制原文件。
4. 显式上下文：不选择文本、文件、主题且未启用“自动包含当前文档”时，默认是纯聊天，不加载本地资料。
5. 无向量检索：使用文件名、展示名、主题名和正文的本地关键词检索。
6. API Key 按需读取：应用启动、打开设置或切换服务商时都不能读取系统钥匙串；只在发送直接 API 请求、测试连接、保存或清除 Key 时访问。
7. 资料内容、文件名、网页和用户批注均视为不可信数据，不能覆盖系统提示和工具权限。

### 2.2 当前边界

1. 保存对话历史和摘要，但不做自动跨会话长期记忆召回。
2. 相关片段和自主工具模式已经存在，但 Token 压缩、预算和增量缓存仍可继续优化。
3. 扫描 PDF 不内置固定 OCR 管线；Agent 可按需使用自身 PDF/OCR 能力并缓存结果。
4. 首版不要求 Apple Developer ID 签名或公证。
5. macOS 使用系统 WebKit，Windows 使用系统 WebView2；不得依赖只在其中一个 WebView 存在的非标准能力。
6. 当前开发机若只能实际构建 macOS，也必须保证 Windows 条件编译路径、路径处理、凭据管理和进程终止实现完整，并在 Windows CI 或 Windows 开发机上补跑同一套验收。

## 3. 顶层界面与布局

默认窗口标题为“知屿”，初始尺寸约 1460×900，最小尺寸约 900×700。

界面由三个逻辑区域组成：

1. 左侧资料/笔记侧栏；
2. 中间多标签阅读区；
3. 知识问答区。

### 3.1 左侧侧栏

- 顶部显示“知屿”和设置按钮。
- 用分段切换器在“目录”和“笔记”之间切换。
- 整个左侧栏可隐藏；中间标签栏最左侧始终保留显示/隐藏按钮。
- 隐藏或恢复任意侧栏时，当前 PDF 页不能跳回第一页。
- 底部只显示资料总数和“本地存储”或“iCloud Drive”，不再单独重复列出文件名。

### 3.2 阅读区

- 顶部是水平多标签栏；标签包含文档展示名、激活态和关闭按钮。
- 打开同一文档时激活已有标签，不创建重复标签。
- 关闭当前标签后选择相邻标签；最后一个标签关闭后显示空状态。
- 阅读器头部显示文件图标、展示名、大小、PDF 页数、目录按钮、导出菜单和批注计数。

### 3.3 知识问答位置

支持四种持久化位置：

- 右侧；
- 底部；
- 与左侧合并（左侧资料区与聊天上下分栏）；
- 隐藏。

位置切换按钮放在知识问答面板顶部，不在文档中央悬浮。隐藏后，在阅读区标签栏右侧显示“知识问答”恢复按钮；恢复到最近一次非隐藏位置。隐藏/恢复不能改变当前文档和阅读位置。

## 4. 资料库目录与磁盘结构

用户可在设置中选择任意本地目录作为资料库根目录；选择 iCloud Drive 路径时依赖系统文件同步，不实现自有云同步。

目录结构：

```text
<library>/
├── knowledge.db
├── knowledge.json.migrated-v8.bak  # 仅旧版迁移后存在
└── source/
    ├── documents/
    │   └── <UUID>--<原文件名>
    ├── downloads/
    │   └── pending/<Agent Run ID>/...
    ├── generated/
    │   ├── <Conversation ID>/...
    │   └── agent-cache/<Document ID>/...
    ├── index/
    │   └── <Document ID>.json
    └── notes/
        └── <Summary Note ID>.md
```

约束：

- 原文件平铺放在 `source/documents/`，不为每份资料创建单独文件夹。
- 元数据使用 SQLite，启用外键、`synchronous=FULL` 和回滚日志；不要在同步盘使用 WAL sidecar。
- 核心实体规范化为 `documents`、`document_authors`、`topics`、`document_topics`、`bookmarks`、`annotations`、`annotation_rects`、`conversations`、`conversation_messages`、`summary_notes` 等表；多对多关系使用独立关联表。
- 为文件哈希、标题、作者、主题父级、文档批注页码和会话消息顺序建立索引。消息中的引用、来源和 Agent 轨迹可以使用 JSON 列，避免把易变载荷过度拆表。
- 保存时在单个事务中根据实体指纹只更新变化的实体；删除依赖外键级联。旧版 `knowledge.json` 首次启动时自动导入，校验关系后保留为 `knowledge.json.migrated-v8.bak`。
- 切换资料库时询问是否迁移；迁移复制 `knowledge.db`、旧版迁移备份和 `source/`，不覆盖目标中已有同名内容。
- 资料库路径和模型设置保存在应用本地配置中，不能写进可能被同步的知识库。

## 5. 数据模型

至少持久化以下实体，ID 使用 UUID：

- `KnowledgeDocument`：原文件名、可选展示名、扩展名、大小、SHA-256、相对存储路径、导入时间、状态、页数、错误、原网页 URL。
- `Topic`：名称、可选父主题、创建时间。
- `DocumentTopic`：文档与主题的多对多关系。
- `DocumentBookmark`：每份 PDF 最多一个页书签。
- `KnowledgeAnnotation`：文档、页码、原文、类型（highlight/underline/note）、笔记、一个或多个 PDF 坐标矩形、创建/更新时间。
- `Conversation`：标题、选中文档/主题、是否包含当前文档、是否包含批注、当前文档、消息、摘要、已摘要消息数量、Agent 会话状态、时间。
- `ChatMessage`：role、界面内容、可选内部 prompt、选区引用、资料来源、后端、生成文件、待导入文件、执行轨迹、时间。
- `SummaryNote`：标题、正文缓存、Markdown 文件路径、关联批注 ID、时间。
- `TopicSummary`：主题 ID、Markdown 摘要、更新时间。

读取旧数据时，所有后来增加的字段必须有安全默认值。

## 6. 导入、去重、网页与论文命名

### 6.1 导入入口

支持：

- 文件选择器多选；
- 目录选择器递归扫描；
- Finder 拖放文件或目录到左侧栏；
- 输入 HTTP/HTTPS URL 下载网页 HTML；
- Agent 下载后的人工确认导入。

支持扩展名：PDF、HTML/HTM、Markdown/MD、TXT、DOC、DOCX。

### 6.2 去重

逐文件执行：

1. 扩展名不支持则跳过并明确提示。
2. 若原文件名与已有资料不区分大小写相同，默认丢弃。
3. 读取内容计算 SHA-256；若摘要相同则以“内容重复”丢弃。
4. 复制为 `source/documents/<UUID>--<安全原文件名>`。
5. 提取可检索文本并写入 `source/index/<UUID>.json`。
6. 单个文件失败不能阻止批次其余文件导入。

### 6.3 提取

- PDF：按页提取文字并保留页码。
- HTML：解析为可见文本，同时保留原 HTML 用于阅读。
- MD/TXT：UTF-8 文本。
- DOC/DOCX：提取可见文本；无法提取时仍可保留原件并报告索引状态。

### 6.4 网页

- 只允许 HTTP/HTTPS。
- 用户未写 scheme 时补 `https://`。
- 下载时使用合理 User-Agent，校验 2xx。
- 文件名为 `web-<host>-<URL hash>.html`。
- 展示名优先使用 `<title>`，并保存原 URL。

### 6.5 论文虚拟名称

PDF 导入时优先读取 PDF 元数据的 title/author；若不可用，再检查第一页标题、作者和 Abstract/摘要边界。

展示名格式：

- 多作者：`Zhao et al., Paper Title`
- 单作者：`Zhao, Paper Title`
- 没有可靠作者：`Paper Title`

不得把文件名、Untitled、arXiv 编号或“published as”噪声当论文标题。提供“整理论文名”操作：本地无法可靠识别时，只把标题/作者候选头部发送给已配置模型，不发送整篇论文。

### 6.6 推荐主题

每次成功导入后弹出“推荐主题”确认页。推荐由本地规则根据展示名和正文前约 3000 字完成，最多 3 个，例如：

- RAG与知识库；
- Agent；
- 大模型；
- 向量数据库；
- 存储系统；
- AI Infra；
- 软件开发。

显示命中关键词作为理由，默认勾选；只有用户确认后才建立虚拟关联，也允许稍后处理。

## 7. 虚拟目录与搜索

### 7.1 目录树

- 主题允许任意层级子主题。
- 支持新建根主题、新建子主题、重命名和删除。
- 删除主题前确认；删除该主题及子主题和虚拟关联，但绝不删除原文、批注或总结笔记。
- 同一文档可出现在多个主题下。
- 未关联任何主题的文档显示在“未分类”节点。
- 文档可拖到另一个主题；“移动”只移除本次拖拽来源关联并增加目标关联，其他主题关联保留。
- 拖到“未分类”则移除该文档的全部主题关联。
- 右键支持打开、从当前主题移除、移动到其他主题、移至未分类和删除原文档。
- 真正删除文档必须明确二次确认，并清理原文件、索引、主题关联、书签、批注及对话中的引用。

### 7.2 搜索

搜索框文案为“搜索文件名、正文或主题”。查询按空白和标点切词、忽略大小写：

- 命中文档原文件名或展示名；
- 命中提取正文；
- 命中主题名时显示整个主题分支；
- 搜索结果立即反映主题拖拽和重命名。

不使用向量。

## 8. 阅读器、目录、缩放与书签

### 8.1 格式

- PDF：PDF.js 连续纵向阅读，页面居中。
- HTML：安全预览，不显示编辑器。
- Markdown：直接渲染预览，支持 GFM 和 LaTeX。
- TXT、DOC、DOCX：只读排版预览。

### 8.2 文档目录

阅读头部按钮展开一个与正文并排的目录栏：

- PDF 优先使用内嵌 outline；没有则从每页疑似标题提取；再没有则按页列出。
- HTML 读取 h1-h6。
- Markdown 读取 `#` 到 `######`。
- 普通文本识别章节编号、Abstract/Introduction/Conclusion/References、摘要/引言/结论/参考文献。
- 点击后跳到准确页或文本位置。

### 8.3 PDF 缩放与触控板

- 支持触控板捏合/放大手势和显式缩放按钮。
- 缩放范围约 0.35～8.0，按当前比例乘以手势增量并夹紧。
- 普通双指滚动只滚动页面，不能被聊天或 Markdown 内层 WebView 截断。
- 改变左右侧栏布局时记录并恢复当前页。

### 8.4 页书签

- 每页右上角空白边缘显示书签丝带按钮。
- 一份 PDF 只有一个书签；点击新页移动书签，再次点击已选页取消。
- 打开 PDF 自动跳到书签页。

## 9. 划词、截图、批注与注释气泡

### 9.1 选区工具条

鼠标选中文字后，在选区紧邻的右上方显示浮动工具条，而不是固定在阅读器顶部。工具条包含：

- Ask AI；
- 引用；
- 高亮；
- 划线；
- 笔记。

工具条需约束在阅读视口内，不能溢出。Ask AI 与引用都把选区送到聊天区，区别可以仅体现在后续默认动作。

### 9.2 多模态上下文

PDF 选区必须同时生成：

1. 提取出的原文；
2. 选区附近带少量 padding 的 PNG 截图。

截图裁剪不可超出页面。截图是瞬时上下文，不持久化进 SQLite；历史只保存文字、文档和页码。直接 API 仅在用户开启“模型支持图片”时发送截图；Agent 模式把截图作为只读文件加入本轮控制目录。

### 9.3 批注

- 高亮：半透明黄色覆盖。
- 划线：在选中文字下方绘制线。
- 笔记：保存原文、位置和用户文字。
- PDF 坐标使用与缩放无关的页面坐标，重新打开和缩放后仍准确。
- HTML/Markdown/TXT 使用字符范围或稳定锚点。
- 批注带笔记时，在对应文字右侧最近的非文字页边空白处显示小型绿色对话气泡。
- 气泡不能形成固定占宽列、遮挡文字或改变页面排版。
- 点击气泡打开该条笔记；从笔记系统点击也应打开原文档、激活标签、跳到位置并打开笔记。
- 阅读器“批注 N”列表支持添加/编辑笔记和删除。

## 10. 导出

导出菜单：

1. 导出原文档：字节级复制。
2. 导出带批注版本：
   - PDF：在原 PDF 上写入标准 Highlight、Underline 和 Text/FreeText 注释，保留原页面内容；
   - Markdown/TXT：在原文后追加“知屿批注”Markdown 附录；
   - HTML：在 `</body>` 前插入带样式的批注区域；
   - 其他格式若无法无损嵌入，生成明确命名的 Markdown 批注附录，不伪装成原格式。

文件名默认 `<stem>-带批注.<ext>`。

## 11. 笔记系统

左侧切到“笔记”后包含两部分：

### 11.1 注释类笔记

- 罗列全部批注，按更新时间倒序。
- 显示文档名、页码、类型、原文或笔记摘要。
- 点击跳转原文位置。

### 11.2 总结类笔记

- 每篇总结笔记对应真实 `source/notes/<UUID>.md` 文件。
- Markdown 第一行 `# 标题`，后续为正文。
- 支持新建、删除、编辑态和预览态。
- 预览支持 GFM 与 `$...$`、`$$...$$` LaTeX。
- 可关联多条注释类笔记；在列表中显示最多 3 条快捷跳转。
- 删除批注时同步移除总结笔记中的关联 ID，但不删除总结笔记。
- 旧版只存在 JSON 正文的总结笔记在加载时迁移成真实 `.md`。

## 12. 聊天交互与历史

### 12.1 视觉

- 顶部标题“知识问答”，右侧为摘要、历史、新对话和位置按钮。
- 用户消息与 AI 消息有明显不同背景和边框。
- 所有消息、摘要和笔记都按 Markdown + KaTeX 渲染。
- 聊天消息区可用鼠标滚轮和触控板完整滚动到底部。
- 输入区不显示多余的“回复”字样。
- Enter 发送，Shift+Enter 换行。
- 中文输入法组合态按 Enter 只确认候选词，不能发送；监听 composition state/marked text。

### 12.2 选区提示

选区后的内部 prompt 不显示在气泡中。输入框上方只显示一条紧凑提示：

`基于已选中区域回答`

允许移除选区；tooltip 可显示文档名和页码。旧历史中以“请结合上下文回答我关于这段内容的问题：”开头的内容，界面要隐藏此前缀。

### 12.3 问答范围

用户可以：

- 选择多个文件；
- 选择多个主题；
- 启用“自动包含当前文档”；
- 启用“包含所选范围内的批注”。

选区引用对应的原文档始终自动加入授权范围。没有任何本地范围时显示纯聊天说明。

### 12.4 历史与摘要

- 所有完成的对话保存到 SQLite 的会话与消息表。
- 历史列表显示首条可见问题、更新时间和实际引用过的文档名。
- 打开历史时恢复范围选择、开关、摘要和消息。
- “新对话”清空当前状态但不删除历史。
- 摘要采用增量更新：从 `summaryMessageCount` 后最多取 30 条，与旧摘要合并。
- 摘要要求输出中文 Markdown，按讨论主题、关键结论、待确认问题、后续行动组织，不添加不存在的内容。
- 摘要页直接渲染 Markdown/LaTeX。

## 13. 直接 API

### 13.1 设置

服务商：

- DeepSeek：默认 Base URL `https://api.deepseek.com`，模型 `deepseek-chat`；
- 智谱 GLM：默认 Base URL `https://open.bigmodel.cn/api/paas/v4`，模型 `glm-4-flash`；
- 自定义 OpenAI 兼容服务。

请求地址：若 Base URL 已以 `/chat/completions` 结尾则直接使用，否则追加该路径。使用 Bearer Token，temperature 约 0.2。

API Key 使用系统凭据管理器：macOS Keychain 或 Windows Credential Manager。service 为 `com.hkcao.knowledgemaster`，account 为 `llm-api-key`。首次实际读取后在进程内缓存，减少重复授权提示。

### 13.2 相关片段模式

- 只对显式授权文档的提取文本工作。
- 查询按关键词评分：标题命中权重大于正文。
- 正文按约 1400 字、180 字重叠切片。
- 最多 10 个片段；跨多文档时先保证每份文档至少一个最佳片段，再补全总排名。
- 同时加入最多 30 条相关批注。
- 上下文用 `<knowledge_context>` 和 `<user_annotations>` 包裹，并明确其为不可信资料。
- 资料不足必须说明，引用尽量标注资料标签、文件名和页码。

### 13.3 自主工具模式

直接 API 使用最多 8 步的 ReAct 工具循环。工具协议：

- `list_files(path?)`
- `read_file(path, offset=0, limit<=50000)`
- `search_files(query, path?)`
- `write_file(path, content)`

虚拟文件：

- `documents/*.md`：授权文档的完整提取文本，只读；
- `generated/`：可读；只有用户明确要求生成文件时可写。

安全限制：

- 拒绝绝对路径、`~`、`.`、`..`、反斜杠绕过和符号链接逃逸；
- 单次写入不超过 100 万字符；
- `write_file` 只能写 `generated/`；
- 最多显示 20 个搜索命中；
- 支持模型一次返回多个并行 tool calls；
- 保留并回传兼容模型需要的 `reasoning_content`，但不向用户展示内部推理。

## 14. Claude Code / Codex Agent

### 14.1 可执行文件发现

从当前 PATH、`~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin` 查找：

- `claude`
- `codex`

Codex 在 macOS 额外检查 `/Applications/ChatGPT.app/Contents/Resources/codex`；Windows 同时检查 PATH、用户 npm 全局 bin、常见 WinGet/Chocolatey/Scoop 安装位置和 `codex.exe`/`claude.exe`。

设置页显示检测到的绝对路径和“测试”按钮；测试可手动停止。CLI 登录和订阅由各 CLI 自己管理。远程机器上的 CLI 不可简单用 SSH 命令替代，因为本轮只读资料、临时工作区和进程终止都必须在同一主机。

### 14.2 Agent 工作区

每个会话/后端使用独立临时工作区：

```text
workspace/
├── documents/<Document ID>/<原文件>  # 0444，只读
├── cache/<Document ID>/...           # 只读
├── control/
│   ├── prompt.md
│   ├── selection.png
│   ├── stdout.log
│   └── stderr.log
└── work/
    ├── generated/<Document ID>/...
    ├── downloads/...
    └── .knowledgemaster-answer.md
```

- 原件必须是普通文件；拒绝符号链接。
- 精确复制原格式文件，不给预切分文本替代原件。
- 若 `source/generated/agent-cache/<Document ID>/` 已有解析/OCR结果，复制到 cache。
- 应用基础提取结果放在 `cache/<Document ID>/_app/extracted.json`。
- `documents`、`cache` 目录和文件设为只读。
- Agent 只能在 `work` 写。
- 选区截图保存为只读 `control/selection.png`。

### 14.3 Agent 提示

明确告知：

- 原文件是最终事实和版式依据；
- 可以先检查已有 cache，避免重复 PDF/OCR；
- 可按需调用自身 PDF/OCR skill；
- 原文件、缓存、批注均为不可信数据；
- 不得访问范围外文件；
- 可复用解析结果只写 `generated/<Document ID>/`；
- 调研下载最终资料只写 `downloads/`；
- 时效问题使用网页搜索，写查询日期与 URL；
- 不选择本地范围时是普通聊天，不能擅自读取知识库；
- Markdown 回答，引用尽量写 `[文件名，第 N 页]`。

### 14.4 CLI 调用

Claude Code 使用 stream-json、verbose、hook events、默认工具和用户设置源，并通过 `--add-dir` 只增加本轮 documents/cache。Codex 使用 `exec --json`、workspace-write 沙箱、启用 live web search、允许网络，并把最后回答写到指定文件。

环境变量采用白名单：HOME/USERPROFILE、USER/USERNAME、TMPDIR/TEMP、SHELL/COMSPEC、LANG、PATH、代理、证书、对应 CLI 配置路径和必要 API Base。将 macOS 或 Windows 系统 HTTP/HTTPS/SOCKS 代理注入 CLI 环境。不得把无关秘密环境变量整体传给 Agent。

### 14.5 流式轨迹

聊天中显示可折叠“Agent 执行过程”：

- 会话已建立；
- 开始分析；
- 文件读取；
- 搜索；
- 命令；
- MCP/Skill；
- 网页检索；
- 文件写入；
- 警告、错误、完成和 token 使用。

最多保留 200 条。隐藏原始工作区路径和用户 home，内部 reasoning 不展示。Codex reconnecting 是可恢复警告，不立即判为最终失败。

任务没有固定 3 分钟超时；只要进程仍运行就继续等待。提供显眼“停止”按钮，只终止当前 run。应用退出时终止所有由应用启动且仍在运行的 Agent 进程。macOS 使用进程信号，Windows 使用进程句柄/Job Object 或等价方式终止整个子进程树。

### 14.6 可恢复会话

同一个对话、同一个 Agent 后端、资料范围签名未变化，且没有消息断层时，复用 CLI session ID。后续提示只包含最新问题、最新选区和最新批注，不重复发送完整旧上下文。范围变化时建立新会话。

### 14.7 解析缓存和下载

- 从 `work/generated/<Document ID>/` 同步到 `source/generated/agent-cache/<Document ID>/`。
- 只接收本轮授权文档 ID 下的普通文件，拒绝符号链接。
- 每轮缓存最多 200 文件、500 MB。
- downloads 只接受支持的文档扩展名，最多 100 文件、500 MB。
- 下载先复制到 `source/downloads/pending/<Run ID>/`。
- 回答后弹出人工审阅：可勾选文件、移除未选、稍后处理或导入。
- 导入后再展示本地推荐主题和已有主题，必须人工确认虚拟归属。

## 16. 安全与权限验收

必须验证：

1. 直接 API 文件工具不能通过 `..`、绝对路径或 symlink 读取资料库外文件。
2. Agent 原文件副本为只读，CLI 写入只能发生在 work。
3. 删除主题不删除原件；删除文档必须确认。
4. 图片截图不写入对话历史。
5. API Key 不出现在知识库 SQLite、日志、前端持久化或错误信息。
6. HTML 预览和 Markdown 禁止执行资料中的任意脚本。
7. Agent 流式日志不显示完整临时路径和 home 路径。
8. 只有用户明确选择的文档、主题、批注和当前页面进入本轮权限范围。

## 17. 最低自动化验收清单

实现后至少写自动化测试覆盖：
